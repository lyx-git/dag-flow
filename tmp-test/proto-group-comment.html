💬 批注✕
官方 comment 组件（节点级批注），同样是画布装饰。
  • 真容器语义：折叠/展开、组内整体移动、跨组拖入拖出、组内自动布局
  • 代价 ①：def.nodes[].parent 新字段 → 三处 schema 同步（host types / host 校验 / client JsonView）
  • 代价 ②：装饰节点（group/container/comment）必须排除出执行图，否则引擎按节点执行 → UNKNOWN_NODE_TYPE
  • 代价 ③：拖拽/连线/选中/删除/自检/运行日志全部要逐条回归（CDP 31 项）
  • 现状：@flowgram.ai/free-group-plugin@1.0.15 存在（与本项目其它 flowgram 包同版本），但尚未安装

对比与取舍

维度方案 A：画布装饰（推荐）方案 B：官方容器
你的核心诉求（大图可读性）✅ 达到：能分区、能写备注、拖动一框一起搬✅ 达到，且能折叠收起省空间
执行图 / 自检 / 运行日志零影响（装饰存在 def.canvas，引擎看不到）需显式排除装饰节点，逐个回归
数据结构新增根字段 canvas（schema 加一条 + JsonView 同步）新增节点级 parent（三处 schema + 拖拽语义）
新依赖无+1 个 flowgram 包（打进入 bundle，用户装机负担不变）
工作量1 轮（装饰层 + 编辑 + 持久化 + 断言）2-3 轮
风险低（不碰节点/连线交互，只在最底层画）中-高（容器会改变命中测试与拖拽链路，本项目对此极敏感）
我的建议：先做 A（花的是一轮的代价，拿到你要的可读性）；等你真用了一阵、确实需要"折叠收起 / 跨组拖拽"再上 B —— 那时 A 的数据结构（def.canvas）可以与 B 共存，不白做。
