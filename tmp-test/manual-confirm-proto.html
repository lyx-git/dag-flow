✋ 人工确认节点（manual）· UI 原型

现状：manual 节点是 v0.1 空壳——run() 立即返回 success，不暂停、不等待，工作流一路跑完。 本原型是「方案 A：真暂停 + 恢复」的 UI 形态，用的是真实 --wf-* token 与既有弹窗几何（宽 680 / 圆角 14 / 右上 ✕）。 按钮都能点：点头部「⏸ 等待人工确认」徽标可重开弹窗，确认/取消会走完整个状态流转。

1 · 头部运行徽标状态族（新增 ⏳ 运行中 / ⏸ 等待人工确认 两态）

等待态用 accent 描边 + 2s 呼吸光晕，与「运行中」区分：运行中是实心浅蓝、等待是可点徽标（描边+光标手型）。

2 · 确认弹窗（变体 A —— 我推荐的形态）

标题「⏸ 等待人工确认」+ 右上 ✕（= 只关弹窗，保持等待，可从徽标重开）；正文 = 节点标识 + prompt 原文 + 可选备注；底部左「✕ 取消本次运行」（终止整个运行）右「✓ 确认并继续」（主按钮）。

3 · 变体对比（需要你定档：取消运行放哪 / ✕ 什么语义）

变体 B：底部只留一个主按钮「✓ 确认并继续」，终止运行降级为标题右侧的小字链接——底部更干净， 但「终止运行」的可发现性变差（要点小字才看得到）。
变体 C：无备注输入框，纯审批闸门（你已选「可选备注文本」，此变体仅作对照——若嫌输入框碍事就选它）。

5 · 中断态（刷新可恢复；dsh web 重启后运行丢失）

等待状态存在 host 内存 → 刷新页面/切走面板都能查回来；但 dsh web 重启会丢，此时点徽标只查到「查无此运行」→ 给这个明确的收尾弹窗，而不是静默变成僵尸。

6 · 需要你拍板的 3 个点（其余我按推荐实现）

① 取消运行的位置
变体 A（底部左「✕ 取消本次运行」+ 右「✓ 确认并继续」）——两个动作都在视线内，误触概率低（danger 色区分）。变体 B 把终止降级为标题小字链接。
② 右上 ✕ 的语义
只关弹窗、运行保持等待（推荐，可从头部 ⏸ 徽标重开；符合项目「✕ 一律只关闭」的既有约定）。另一选择：✕ = 取消运行（危险操作藏在 ✕ 里，不推荐）。
③ 备注文本的去向
用户填的备注进入节点输出 manual_ok.out.value，下游用 {{manual_ok.out.value}} 取；不填则为空串。确认事实写入 out.confirmed = true、确认时间 out.confirmedAt。

7 · 实现契约（供你核对语义，不是 UI）

POST /api/dag-flow/run → 立即返回 { ok:true, status:'awaiting', runId, awaiting:{ nodeId, prompt } }（不再 hold 长连接）
GET /api/dag-flow/run/status?runId= → { status:'running'|'awaiting'|'completed', awaiting?, summary? }（刷新后能查回暂停态，节点徽标也随之更新）
POST /api/dag-flow/run/resume { runId, value } → 唤醒挂起的 manual 节点并继续，hold 到跑完返回完整 summary（复用现有成功/失败展示链路）
DELETE /api/dag-flow/run?name= → 取消运行（已有）；若正卡在 manual，同时唤醒并置为已取消
非交互路径（CLI /workflow 工具、subflow 子工作流内部）：自动通过，输出 out.confirmed=true + out.autoPassed=true，并记一条 warning 日志
持久化边界：awaiting 注册表在 host 内存；运行记录（.dag-flow/runs/<runId>.json）仍只在结束时写——暂停中的运行不会出现在运行历史里
